## 1. 文件定位

三位工程師分別開發不同功能，最後可能以檔案拖拉方式整合。以下文件提供最低限度的共同語言，降低視覺、API 與權限實作差異；在沒有共用 Git repository、整合負責人及交付規則的情況下，不能保證完全無痛整合。

業務功能、角色及資料範圍以 [地礦 AI 功能模組與開發分工說明](地礦AI_功能模組與開發分工說明.md) 為準。雛型只用於辨識畫面與互動，不代表後端功能已完成。

## 5. 可拖拉整合建議

- 每個功能集中在自己的 `modules/<module>` 或後端同名模組資料夾。
- 模組內自行管理頁面、route、store、DTO、service 與 API 呼叫。
- `core`、共用 UI、登入狀態、API client、角色及資料範圍只保留一份，不由三人各自建立不同版本。
- 跨模組只交換固定識別碼，例如 `projectId`、`monitoringAreaId`、`variationPointId`、`surveyCaseId`、`userId`。
- 不以畫面中文名稱、縣市名稱或陣列順序作為資料關聯鍵。

## 6. 共同底線

- 同一概念使用同一個中英文名稱。
- 前端隱藏按鈕不能取代後端權限檢查。
- 下載、匯出、圖表及圖台資料同樣套用角色與資料範圍。
- 技術與 API 細節尚未經工程確認者，保留為建議，不寫成既有功能。
- 本版不規範單元測試、整合測試、Git flow、CI/CD、交付異動紀錄及資料庫 Migration 流程。
